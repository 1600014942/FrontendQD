# acucompute.com 首页“质量提升”叙事微调方案

状态：待审阅，未修改网站代码

日期：2026-09-14

目标页面：`https://acucompute.com/`

生产源码：`/root/jerry/FrontendQD`

## 1. 调整目标

把首页的第一印象从：

> 在质量达标前提下，通过模型路由节省 Token 和成本

调整为：

> 针对不同任务动态配置模型、验证和回退路径，持续提高 AI 输出的准确性、稳定性与可用性

成本效率仍然保留，但降为质量提升之后的第二层价值。用户进入首页后，首先理解“清度帮助 AI 产出更好的结果”，继续下滑后再看到成本测算。

## 2. 修改原则

1. 只改首页叙事，不改产品能力、路由逻辑、后端、接口或数据结构。
2. 不改主视觉球体、Logo 图、整体黑白视觉、页面结构和导航位置。
3. 不改 `/acu-index/`、`/articles/`、`/book-demo/` 等后续页面。
4. 不把现有省钱数字直接改名为“质量提升率”，避免制造没有生产数据来源的质量指标。
5. 首页后半段的节省测算器保留，作为“质量优先之后仍可获得成本效率”的次级证明。
6. 图表语义必须和横纵轴一致，不能只换标题而保留一张本质上仍在讲省钱的图。

## 3. 建议后的首页叙事顺序

1. **首屏承诺**：让每一次 AI 调用产出更好的结果。
2. **问题解释**：固定模型忽略任务差异，不能始终得到最合适的结果。
3. **解决方式**：按任务动态配置模型、验证和回退，使更多输出稳定达到业务标准。
4. **持续提升**：真实执行和用户反馈形成私有质量闭环，让后续判断越来越贴合客户标准。
5. **次级收益**：在质量优先的前提下，再展示可量化的成本优化空间。

## 4. 逐项修改清单

### 4.1 首页 SEO 与分享摘要

| 位置 | 当前 | 建议 |
| --- | --- | --- |
| 页面标题 | 清度科技｜AI 产能配置基础设施 | 清度科技｜AI 质量优化与产能配置基础设施 |
| Meta / OG 描述 | 释放每一滴 Token 的最大产能。清度科技在质量达标前提下，为每项任务寻找最低成本的合格路径。 | 清度科技通过任务识别、动态模型配置、质量验证与私有反馈学习，让 AI 输出更准确、更稳定、更可用。 |
| OG 主标题 | 释放每一滴 Token 的最大产能 | 让每一次 AI 调用，产出更好的结果 |
| OG 副标题 | AI 产能配置基础设施 | AI 质量优化与产能配置基础设施 |

原因：如果只改可见首屏，搜索结果和微信、Slack 等分享卡片仍会继续讲“最低成本”，叙事会不一致。

### 4.2 首屏主文案

| 位置 | 当前 | 建议 |
| --- | --- | --- |
| H1 第一行 | 释放每一滴 | 让每一次 AI 调用 |
| H1 第二行 | Token 的最大产能 | 产出更好的结果 |
| 说明文字 | AI 产能配置引擎，帮助用户在同样预算下，完成更多高质量任务 | AI 产能配置基础设施，针对不同任务动态匹配模型、验证路径与回退策略，让输出更准确、更稳定、更可用。 |

建议保留当前球体图片、左右布局、字号层级和入场效果，只校正新文案在桌面与手机上的换行。

### 4.3 首屏数据区

当前首屏的“已为开发者节省”“累计节省 Token”“利用率提升”会立即把用户带回省钱叙事。建议把这一区域从无生产数据支撑的动态演示数字，改成三个质量能力支点：

| 小标题 | 大字 |
| --- | --- |
| 理解任务要求 | TASK-AWARE |
| 匹配适合能力 | DYNAMIC |
| 验证并持续学习 | VERIFIED |

同时：

- “清度数据概览”改为“清度质量优化路径”；
- 删除“实时更新”提示以及前端定时递增的省钱、Token 演示逻辑；
- 不在此处展示虚构的“质量提升 29.4%”或“达标率 99%”。

这仍是首屏文字级微调，不新增后台指标，也不改变页面主要布局。

任务名称、模型层级和连线结构保留。该图不再用“高模型层级 = 高成本”作为主要结论，而是说明固定配置没有理解每项任务真正需要的能力组合。

### 4.5 第二张图：任务复杂度与达标率

这一张图目前是全页最强的“省钱证明”：横轴是成本，清度路线与最强模型质量近似相同，但成本是 `1.0×` 对 `3.2×`。只换标题或轴名称会造成图形和语义冲突，因此建议保留同一 SVG 区域和黑白风格，重画为质量曲线。

**图上标题**

| 位置 | 当前 | 建议 |
| --- | --- | --- |
| Kicker | 2. 找到最低成本的合格路径 | 2. 为每项任务匹配更高质量的路径 |
| 主标题 | 同样的任务，以更低的成本完成。 | 根据任务动态配置能力，让更多输出稳定达到业务标准。 |

**新图表定义**

| 图表元素 | 建议 |
| --- | --- |
| 横轴 | 任务复杂度 |
| 纵轴 | 任务达标率 |
| 水平虚线 | 业务质量门槛 |
| 曲线 A | 固定模型：随任务复杂度增加，达标率更早跌破门槛 |
| 曲线 B | 清度动态配置：通过任务识别、模型匹配、质量验证和必要回退，在更大任务范围内保持达标 |
| 底部说明 | 任务越复杂，越需要组合模型选择、质量验证与必要回退。 |

图中删除 `99% / 100% 合格输出`、`1.0× / 3.2× 成本`等未经页面数据源实时支持的精确数字，改用定性曲线和明确的“示意”口径。这样用户看到的是“质量稳定性提高”，不是“用更便宜的模型维持差不多质量”。

## 6. 预计涉及文件

| 文件 | 用途 |
| --- | --- |
| `src/app.ts` | 首页文案、三个内嵌 SVG、首屏演示指标逻辑 |
| `build.mjs` | 仅修改首页 title 和 description |
| `public/og.svg` | 修改分享卡片主副标题 |
| `public/styles.css` | 只在新质量曲线或首屏三项能力排版需要时做小幅适配 |
| `src/shell.html` | 发布时更新 `app.js` cache-busting 版本号 |
| `public/app.js`、`public/index.html` 等 | 由 `npm run build` 生成，不手工维护 |
| `screenshots/` | 更新首页桌面、手机和两张图的审阅截图 |

说明：更新全站共用的 `app.js` 版本号会让构建后的各路由 HTML 出现同一行 query string 变化，但后续页面的可见内容不会变化。
